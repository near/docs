Now that we have successfully created a contract, it's time to build a frontend to provide a user-friendly interface for interacting with it. Up until now, we have been using the CLI to send transactions and view the contract's state. However, frontends offer a more intuitive way for end users to interact with the contract. They can display all the relevant information in one place, allow users to make calls with a simple button click, and only require a wallet as a prerequisite.

---

## Frontend structure

Navigate to the auction frontend.

```bash
cd frontends/01-frontend
```

Here we have a simple Next.js frontend that we'll walk through to understand the basics of creating a frontend for a NEAR smart contract.

For starters, let's take a look at how the code in the frontend is structured by doing a quick overview of the important files.

| File                             | Description                                                                     |
|----------------------------------|---------------------------------------------------------------------------------|
| **_app.js**           | Responsible for rendering the page, initiates the wallet object and adds it to global context  |
| **index.js**          | The main page where the project's components are loaded into and contains most of the logic for the application like viewing the state of the contract and logic for placing a bid |
| **near.js**           | Contains the wallet class that has methods to interact with the wallet and blockchain |
| **context.js**        | Holds the global context - the wallet object and the signed-in account ID - that can be accessed anywhere |
| **config.js**         | Specifies the account ID of the auction contract |
| **Navigation.jsx**    | A component that contains a button to sign users in and out of wallets |
| **Bid.jsx**           | A component allowing a user to make a bid |
| **LastBid.jsx**       | A component that displays the highest bid and when the highest bid will next refresh |
| **Timer.jsx**         | A component that shows how long till the auction is over, or, if over, displays a button to claim the auction and then states the auction is over 
| **amounts.mjs**       | Converts token amounts between decimal strings and their smallest units using integer arithmetic |

To run the frontend, use Node.js 22.12 or newer and install its dependencies:

```bash
cp .env.example .env.local
npm ci
npm run dev
```

## Setting up wallets

To be able to fully interact with the contract - send bids and claim the auction - you'll need a `wallet` to sign transactions. Wallets securely store your private keys and allow you to sign transactions without exposing your private key to the frontend. We use `@hot-labs/near-connect` to let users choose and connect a wallet.

We abstract the connector in our `near.js` file by exposing methods to sign in, sign out, read contract state, and send transactions. The connector is loaded in the browser when needed, while `near-api-js` provides an RPC connection for view calls.

The wallet object is initiated in the `_app.js` file and added to the global context along with the signed-in account. Its `startUp` method restores an existing wallet session and subscribes to sign-in and sign-out events. The effect cleans up those subscriptions when the component unmounts.

```javascript title="_app.js" lines
const wallet = new Wallet({ networkId: NetworkId });

export default function MyApp({ Component, pageProps }) {
  const [signedAccountId, setSignedAccountId] = useState('');

  useEffect(() => {
    let cancelled = false;
    let cleanup;
    wallet.startUp((accountId) => { if (!cancelled) setSignedAccountId(accountId); })
      .then((dispose) => { if (cancelled) dispose(); else cleanup = dispose; })
      .catch((error) => { if (!cancelled) toast.error(error.message); });
    return () => { cancelled = true; cleanup?.(); };
  }, []);

  return (
    <NearContext.Provider value={{ wallet, signedAccountId }}>
      <Navigation />
      <Component {...pageProps} />
      <ToastContainer />
    </NearContext.Provider>
  );
}
```

**Access keys**

On NEAR, in addition to full access keys, we have `function-call access keys` that allow applications to sign calls to specific methods without attaching a deposit. Our `bid` call attaches NEAR, so we send it through the connected wallet for approval.

```javascript title="near.js" lines
async getConnector() {
  this.connectorPromise ??= import('@hot-labs/near-connect').then(({ NearConnector }) =>
    new NearConnector({ network: this.networkId, providers: { [this.networkId]: [RPC_URL] } }));
  return this.connectorPromise;
}

startUp = async (onAccountChange) => {
  const connector = await this.getConnector();
  let active = true;
  const signedIn = ({ accounts }) => {
    if (active) onAccountChange(accounts[0]?.accountId ?? '');
  };
  const signedOut = () => { if (active) onAccountChange(''); };
  connector.on('wallet:signIn', signedIn);
  connector.on('wallet:signOut', signedOut);
  const connected = await connector.getConnectedWallet().catch(() => null);
  if (active) onAccountChange(connected?.accounts[0]?.accountId ?? '');
  return () => {
    active = false;
    connector.off('wallet:signIn', signedIn);
    connector.off('wallet:signOut', signedOut);
  };
};

signIn = async () => (await this.getConnector()).connect();
signOut = async () => {
  const connector = await this.getConnector();
  await connector.disconnect(await connector.wallet());
};
```

## Updating the highest bid

Someone else could have placed a higher bid since the page was loaded. To keep the display up to date, we fetch the contract information every 20 seconds using `setInterval`. A second interval updates the countdown until the next refresh, and both intervals are cleared when the component unmounts.

{/* github-code
url: https://github.com/near-examples/auctions-tutorial/blob/main/frontends/01-frontend/src/pages/index.js
commit: 4678765ea7f2a584b1a6569786d497dcf75f5261
start: 24
end: 63
fname: index.js
*/}

```javascript title="index.js" lines
useEffect(() => {
  const getInfo = async () => {
    const highestBidData = await wallet.viewMethod({
      contractId: AUCTION_CONTRACT,
      method: "get_highest_bid",
    });
    setHighestBid(formatUnits(highestBidData.bid, 24))
    setHighestBidder(highestBidData.bidder)

    const claimedData = await wallet.viewMethod({
      contractId: AUCTION_CONTRACT,
      method: "get_claimed",
    });
    setClaimed(claimedData)

    const auctionEndTimeData = await wallet.viewMethod({
      contractId: AUCTION_CONTRACT,
      method: "get_auction_end_time",
    });
    setAuctionEndTime(auctionEndTimeData)
  }
  getInfo().catch((err) => setError(err.message));

  fetchPastBids();

  const intervalId = setInterval(() => {
    getInfo().catch((err) => setError(err.message));
    setSecondsRemaining(20);
  }, 20000);
  
  const countdownIntervalId = setInterval(() => {
    setSecondsRemaining(prev => (prev === 1 ? 20 : prev - 1));
  }, 1000);


  return () => {
    clearInterval(intervalId);
    clearInterval(countdownIntervalId);
  };
}, []);
```

## Auction end time

The contract stores the end time of the auction in nanoseconds since the Unix epoch (1 January 1970 00:00:00 UTC). The `Timer` component converts this value to milliseconds using `BigInt`, compares it with `Date.now()`, and displays the time left in days, hours, minutes, and seconds.

{/* github-code
url: https://github.com/near-examples/auctions-tutorial/blob/main/frontends/01-frontend/src/components/Timer.jsx
commit: 4678765ea7f2a584b1a6569786d497dcf75f5261
start: 18
end: 36
fname: Timer.jsx
*/}

```jsx title="Timer.jsx" lines
const [time, setTime] = useState(0);
useEffect(() => {
  const update = () => setTime(Math.max(0, Number(BigInt(endTime) / 1_000_000n) - Date.now()));
  update();
  const timer = setInterval(update, 1000);
  return () => clearInterval(timer);
}, [endTime]);

const formatTime = (time) => {
  const allSeconds = Math.floor(time / 1000);
  const days = Math.floor(allSeconds / (3600 * 24));
  const hours = Math.floor((allSeconds % (3600 * 24)) / 3600);
  const minutes = Math.floor((allSeconds % 3600) / 60);
  const seconds = allSeconds % 60;

  return { allSeconds, days, hours, minutes, seconds };
};

const { allSeconds, days, hours, minutes, seconds } = formatTime(time);
```

## Making a bid

To make a bid we call the contract's `bid` function. The input box takes the amount in NEAR, and `parseUnits` converts that decimal string to a `yoctoNEAR` string using exact integer arithmetic. The call attaches that amount as a deposit and requests 300 TGas. Unused gas is refunded.

Here, since the user is changing the state of the contract, not just viewing it, the user needs to sign the transaction. Thus the wallet will pop up displaying the transaction details.

{/* github-code

start: 65
end: 76
fname: index.js
*/}

```javascript title="index.js" lines
const bid = async (amount) => {
  const real_amount = parseUnits(amount, 24)
  let response = await wallet.callMethod({
    contractId: AUCTION_CONTRACT,
    method: "bid",
    deposit: real_amount,
    args: {},
    gas:"300000000000000"
  })
  window.location.reload();
  return response
}
```

```javascript title="near.js" lines
callMethod = async ({ contractId, method, args = {}, gas = '300000000000000', deposit = '0' }) => {
  const selectedWallet = await (await this.getConnector()).wallet();
  const outcome = await selectedWallet.signAndSendTransaction({
    receiverId: contractId,
    actions: [{ type: 'FunctionCall', params: { methodName: method, args, gas: String(gas), deposit: String(deposit) } }],
  });
  if (!outcome) throw new Error('Wallet returned no transaction result');
  if (typeof outcome.status === 'object' && 'Failure' in outcome.status) {
    throw new Error('Transaction failed');
  }
  return getTransactionLastResult(outcome);
};
```

## Claiming the auction

Once the auction is over (the current time is greater than the end time), the timer displays a button to claim the auction. Clicking it calls `claim` on the basic auction contract, which transfers the highest bid in NEAR to the auctioneer. The page reloads after the transaction so the claimed state is displayed.

## Conclusion

In this part of the tutorial, we have implemented a simple frontend for a NEAR contract. Along the way, you have learned how to use the wallet selector to sign the user in and out, how to view the contract’s state, how to sign and send transactions.

While we can see the highest bid, we may want to see the auction's bidding history. Since the contract only stores the most recent bid (to reduce storage costs), we need to use an indexer to pull historical data. In the [next part](./2.2-indexing) of the tutorial, we'll look at querying historical data using an API endpoint.
