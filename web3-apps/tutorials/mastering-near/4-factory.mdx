Since an auction contract hosts a single auction, each time you would like to host a new auction you will need a new contract account. A factory can create that account and initialize the auction for you.

The tutorial repository includes an [auction factory](https://github.com/near-examples/auctions-tutorial/tree/main/factory) for the FT/NFT auction from the previous sections. It stores the account ID of a published [global contract](/smart-contracts/global-contracts), which each new auction references.

---

## Publishing the auction contract

Firstly, we'll need to publish the auction implementation as a global contract. From the root of the tutorial repository, build the FT/NFT auction:

```bash
cd contract-rs/03-bid-with-fts
cargo near build non-reproducible-wasm
```

Publish the compiled WASM under a funded account that you control:

```bash
near contract deploy-as-global use-file target/near/auction_contract.wasm as-global-account-id <global-auction.testnet> network-config testnet sign-with-keychain send
```

Publishing the global implementation incurs a one-time fee. New auctions pay for their own state and a reference to that implementation.

<Info>
Global contracts referenced by account ID follow code updates published by that account. Use a publisher you control and trust: updating its global code updates the implementation used by existing auctions too.
</Info>

## Initializing the factory

The factory stores the global contract account ID in its state. Its `new` method takes that account ID as an initialization argument:

```rust title="lib.rs" lines
#[near(contract_state)]
#[derive(PanicOnDefault)]
pub struct Contract {
    global_contract_id: AccountId,
}

#[near]
impl Contract {
    /// The auction implementation must already be published as a global contract.
    #[init]
    pub fn new(global_contract_id: AccountId) -> Self {
        Self { global_contract_id }
    }

    pub fn get_global_contract_id(&self) -> AccountId {
        self.global_contract_id.clone()
    }
}
```

[See code on GitHub](https://github.com/near-examples/auctions-tutorial/blob/4678765ea7f2a584b1a6569786d497dcf75f5261/factory/src/lib.rs#L6-L23)

{/* /github-code */}

Build the factory and deploy it to a funded factory account. From the auction contract's directory:

```bash
cd ../../factory
cargo near build non-reproducible-wasm

near contract deploy <factory.testnet> use-file target/near/contract.wasm with-init-call new json-args '{"global_contract_id":"<global-auction.testnet>"}'
```

When prompted, choose zero initialization deposit, testnet, and the factory account as the signer.

## Deploying a new auction

The `deploy_new_auction` method takes a name for the new sub-account and the initialization parameters of the FT/NFT auction. It checks that the name is a valid direct sub-account label, the end time is in the future, and enough NEAR is attached.

{/* github-code
url: https://github.com/near-examples/auctions-tutorial/blob/main/factory/src/deploy.rs
commit: 4678765ea7f2a584b1a6569786d497dcf75f5261
start: 30
end: 65
fname: deploy.rs
language: rust
*/}

```rust title="deploy.rs" lines
#[payable]
pub fn deploy_new_auction(
    &mut self,
    name: String,
    end_time: U64,
    auctioneer: AccountId,
    ft_contract: AccountId,
    nft_contract: AccountId,
    token_id: String,
    starting_price: U128,
) -> Promise {
    // Require a single direct subaccount label; dots would create descendants.
    require!(
        !name.is_empty() && !name.contains('.'),
        "Invalid auction name"
    );
    let account: AccountId = format!("{name}.{}", env::current_account_id())
        .parse()
        .expect("Invalid auction account ID");
    require!(
        end_time.0 > env::block_timestamp(),
        "Auction must end in the future"
    );

    let args = AuctionInitArgs {
        end_time,
        auctioneer,
        ft_contract,
        nft_contract,
        token_id,
        starting_price,
    };
    let init_args = near_sdk::serde_json::to_vec(&args).unwrap();
    let required = self.get_required(args);
    let attached = env::attached_deposit();
    require!(attached >= required, format!("Attach at least {required}"));
```

[See code on GitHub](https://github.com/near-examples/auctions-tutorial/blob/4678765ea7f2a584b1a6569786d497dcf75f5261/factory/src/deploy.rs#L30-L65)

{/* /github-code */}

The factory then creates the account, transfers the attached funds, references the global implementation, and calls `init` in one atomic batch. It adds no access keys, so the new auction is [locked](/protocol/accounts-contracts/access-keys#locked-accounts) after initialization.

{/* github-code
url: https://github.com/near-examples/auctions-tutorial/blob/main/factory/src/deploy.rs
commit: 4678765ea7f2a584b1a6569786d497dcf75f5261
start: 67
end: 84
fname: deploy.rs
language: rust
*/}

```rust title="deploy.rs" lines
    // The entire batch is atomic, including initialization. No access key
    // is installed, so the newly created auction account is locked.
    Promise::new(account.clone())
        .create_account()
        .transfer(attached)
        .use_global_contract_by_account_id(self.global_contract_id.clone())
        .function_call(
            "init".to_owned(),
            init_args,
            NearToken::from_near(0),
            Gas::from_tgas(50),
        )
        .then(
            Self::ext(env::current_account_id())
                .with_static_gas(Gas::from_tgas(30))
                .deploy_new_auction_callback(account, env::predecessor_account_id(), attached),
        )
}
```

[See code on GitHub](https://github.com/near-examples/auctions-tutorial/blob/4678765ea7f2a584b1a6569786d497dcf75f5261/factory/src/deploy.rs#L67-L84)

### Preparing the arguments

Compute an end time in nanoseconds. For example, this command prints a timestamp two minutes from now:

```bash
node -e 'console.log((BigInt(Date.now() + 120000) * 1000000n).toString())'
```

Save the following as `auction-args.json`, replacing the placeholders with your auction's details. Choose an end time that leaves you enough time to fund the auction and place bids:

```json
{
  "name": "my-auction",
  "end_time": "<future timestamp in nanoseconds>",
  "auctioneer": "<seller.testnet>",
  "ft_contract": "<ft.testnet>",
  "nft_contract": "<nft.testnet>",
  "token_id": "1",
  "starting_price": "10000"
}
```

The name must be a single sub-account label without dots, and the full account ID must fit within NEAR's 64-character limit. The starting price is expressed in the FT's smallest units.

### Deposit and storage costs

Call `get_required` with an `args` object containing the same initialization parameters, excluding `name`. For example, save this as `auction-cost-args.json` using the same values as above:

```json
{
  "args": {
    "end_time": "<future timestamp in nanoseconds>",
    "auctioneer": "<seller.testnet>",
    "ft_contract": "<ft.testnet>",
    "nft_contract": "<nft.testnet>",
    "token_id": "1",
    "starting_price": "10000"
  }
}
```

```bash
near contract call-function as-read-only <factory.testnet> get_required file-args auction-cost-args.json network-config testnet now
```

The result is the required deposit in yoctoNEAR, encoded as a JSON string. It covers an estimate of state storage plus 0.1 NEAR for outgoing FT/NFT calls. All attached funds go to the new auction account.

{/* github-code
url: https://github.com/near-examples/auctions-tutorial/blob/main/factory/src/deploy.rs
commit: 4678765ea7f2a584b1a6569786d497dcf75f5261
start: 18
end: 28
fname: deploy.rs
language: rust
*/}

```rust title="deploy.rs" lines
/// Fund state storage and leave 0.1 NEAR for outgoing FT/NFT calls.
/// This conservative bound includes the account, global reference, STATE
/// record, and highest bidder (whose ID is at most 64 bytes).
pub fn get_required(&self, args: AuctionInitArgs) -> NearToken {
    let bytes = 512
        + self.global_contract_id.as_str().len()
        + near_sdk::borsh::to_vec(&args).unwrap().len();
    env::storage_byte_cost()
        .saturating_mul(bytes as u128)
        .saturating_add(NearToken::from_millinear(100))
}
```

[See code on GitHub](https://github.com/near-examples/auctions-tutorial/blob/4678765ea7f2a584b1a6569786d497dcf75f5261/factory/src/deploy.rs#L18-L28)

{/* /github-code */}

Attach the quoted deposit when creating the auction:

```bash
near contract call-function as-transaction <factory.testnet> deploy_new_auction file-args auction-args.json prepaid-gas '300 Tgas' attached-deposit '<quoted-deposit> yoctoNEAR' sign-as <your-account> network-config testnet sign-with-keychain send
```

The new account will be `my-auction.<factory.testnet>`. Successful creation returns `true`. If the creation batch fails, the callback returns `false` and refunds the deposit to the caller.

Before accepting bids, transfer the NFT to the new auction account and register the auction, bidders, and seller with the FT contract's `storage_deposit` method. Bidders then call `ft_transfer_call` on the FT contract with the auction as the receiver and exactly 1 yoctoNEAR attached, as described in [Bidding with FTs](/web3-apps/tutorials/mastering-near/3.2-ft).
