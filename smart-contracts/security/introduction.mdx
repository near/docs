Smart contracts handle assets and shared state in an adversarial environment. This section explains common mistakes, shows how an attacker can use them, and describes the corresponding defense.

<Card title="Start with the checklist" icon="list-check" href="/smart-contracts/security/checklist" horizontal>
  Review access control, storage, funds, asynchronous calls, and testing before mainnet deployment.
</Card>

## Security topics

<Columns cols={2}>
  <Card title="Cross-contract calls" href="/smart-contracts/security/cross-contract-calls/callbacks">
    Safely handle asynchronous results, refunds, and callbacks.
  </Card>
  <Card title="Reentrancy attacks" href="/smart-contracts/security/cross-contract-calls/reentrancy">
    Keep state safe while cross-contract operations are pending.
  </Card>
  <Card title="Storage cost attacks" href="/smart-contracts/security/storage">
    Prevent unbounded state growth from locking your contract's balance.
  </Card>
  <Card title="One yoctoNEAR" href="/smart-contracts/security/one_yocto">
    Require a deposit-capable key for sensitive methods.
  </Card>
  <Card title="Front-running" href="/smart-contracts/security/frontrunning">
    Avoid revealing valuable inputs before they execute.
  </Card>
  <Card title="Sybil attacks" href="/smart-contracts/security/sybil">
    Avoid treating multiple accounts as independent people.
  </Card>
  <Card title="Randomness" href="/smart-contracts/security/random">
    Choose a randomness design that matches the value at risk.
  </Card>
</Columns>

## Report a vulnerability

Report vulnerabilities in the protocol, core contracts, or web applications through the [NEAR bug bounty program](https://hackenproof.com/company/near/programs).

For a broader introduction, watch [Timur Güvenkaya's smart contract security series](https://www.youtube.com/watch?v=DrRr6nru0no).
