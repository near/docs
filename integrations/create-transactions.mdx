To construct & process transactions you can use one of our API libraries, such as [`near-api-js`](/tools/near-api). There are many ways to create transactions but for this example we'll show you two ways to create a simple token transfer transaction.

- [HIGH LEVEL](#high-level-create-a-transaction) - _easiest way to create a transaction_
- [LOW LEVEL](#low-level-create-a-transaction) - _performs the exact same transaction as above, but deconstructs the entire process for those curious about each step_

At the core, all transactions require the following:

- `signerId` _(account ID of the transaction originator)_
- `signerPublicKey`
- `receiverId` _(account ID of the transaction recipient)_
- `nonceForPublicKey` _(each time a key is used the nonce value should be incremented by 1)_
- `actions` _( [[click here]](/protocol/transactions/transaction-anatomy#actions) for supported arguments)_
- `blockHash` _(a recent block hash (within the configured block-based validity period) to prove the transaction was recently created)_

See [Transaction Class](https://github.com/near/near-api-js/blob/2546c85354ab888dc1f559b0e54cfac51f03b484/src/transactions/schema.ts) for a more in depth outline.

## HIGH LEVEL -- Create a transaction

### Setup

1. Use Node.js 24.11 or later and install the SDK version used in this example:

```bash
npm install near-api-js@7.3.1
```

2. Use a funded testnet account with an ED25519 full-access key. Put its secret key in a local `.env` file as `SENDER_PRIVATE_KEY=ed25519:...` and keep that file out of source control.
3. Combine the JavaScript snippets below, in order, into `send-tokens-easy.mjs`. Set `sender` and `receiver` to your testnet accounts, then run:

```bash
node --env-file=.env send-tokens-easy.mjs
```

This sends 1.5 testnet NEAR. Run one example at a time with the selected access key.

### Imports

Import the account, RPC provider, signer, action helpers, and amount conversion directly from `near-api-js`:

```js
import { Account, JsonRpcProvider, KeyPairSigner, actions, nearToYocto } from "near-api-js";
```

- `Account` - constructs and sends transactions for the sender account
- `JsonRpcProvider` - connects to the network's RPC endpoint
- `KeyPairSigner` - signs with the test account's secret key
- `actions` - constructs transaction actions
- `nearToYocto` - converts a decimal NEAR amount to a `bigint` in yoctoNEAR

### Accounts & Network

Next, you'll need to enter the `accountId` of the `sender` and `receiver`, as well as the `networkId` (`testnet` for this example).

```js
const sender = "sender.testnet";
const receiver = "receiver.testnet";
const networkId = "testnet";
```

### Formatting Token Amounts

When sending NEAR tokens (Ⓝ) during a transaction, the amount needs to be converted into [Yocto](https://en.wikipedia.org/wiki/Yocto-) Ⓝ or (10^-24).

- Use `nearToYocto()` to convert the decimal string into a `bigint` without floating-point rounding.

```js
const amount = nearToYocto("1.5");
```

### Create a Signer

Use a [full access key](/protocol/accounts-contracts/access-keys#full-access-keys) belonging to `sender` to authorize the native transfer. Load the test key from the environment rather than hardcoding it or relying on wallet browser storage.

```js
const privateKey = process.env.SENDER_PRIVATE_KEY;
if (!privateKey?.startsWith("ed25519:")) {
  throw new Error("Set SENDER_PRIVATE_KEY to the test account's ED25519 secret key");
}
const signer = KeyPairSigner.fromSecretKey(privateKey);
```

### Setting up a connection to NEAR

Create the RPC provider and pass it, together with the signer, to `Account`:

```js
const provider = new JsonRpcProvider({ url: `https://rpc.${networkId}.near.org` });
if (await provider.getNetworkId() !== networkId) throw new Error("Wrong network");
const senderAccount = new Account(sender, provider, signer);
```

The `senderAccount` uses this provider and signer to construct and send the transaction.

### Create, Sign, & Send Transaction

Create a `Transfer` action and request finalized execution when sending it:

```js
const result = await senderAccount.signAndSendTransaction({
  receiverId: receiver,
  actions: [actions.transfer(amount)],
  waitUntil: "FINAL",
  retries: 0,
});
console.log(result);
```

This constructs, signs, and sends the transfer, and throws if execution fails. `retries: 0` disables automatic re-signing after a nonce error. Inspect the returned result or open its transaction hash in [NearBlocks Explorer](https://testnet.nearblocks.io/). After a timeout, reconcile the transaction before sending another transfer.

```js
import {

import { createHash } from "node:crypto";
```

Next, you'll need to enter the `accountId` of the `sender` and `receiver`, as well as the `networkId` (`testnet` for this example).

```js
const sender = "sender.testnet";
const receiver = "receiver.testnet";
```

When sending NEAR tokens (Ⓝ) during a transaction, the amount needs to be converted into [Yocto](https://en.wikipedia.org/wiki/Yocto-) Ⓝ or (10^-24).

- Use `nearToYocto()` to convert the decimal string into a `bigint` without floating-point rounding.

```js
const amount = nearToYocto("1.5");
```

### Setting up a connection to NEAR

In this example, we will create a NEAR RPC `provider` that allows us to interact with the chain via [RPC endpoints](/api/rpc/introduction).

```js
const provider = new JsonRpcProvider({
  url: `https://rpc.${networkId}.near.org`

```

### Access Keys

To sign a transaction to send NEAR Ⓝ, we will need a `FullAccess` key to the sender's account.

Load the test account's ED25519 secret key from `SENDER_PRIVATE_KEY`, supplied by the `.env` file in the setup step.

- With this `privateKey`, we can now construct a `keyPair` object to sign transactions.

```js
const privateKey = process.env.SENDER_PRIVATE_KEY;
if (!privateKey?.startsWith("ed25519:")) {
  throw new Error("Set SENDER_PRIVATE_KEY to the test account's ED25519 secret key");
}
const keyPair = KeyPair.fromString(privateKey);
```

### Transaction Requirements

As stated before, all transactions require six parts:

1. [`signerId`](#1-signerid)
2. [`signerPublicKey`](#2-signerpublickey)
3. [`receiverId`](#3-receiverid)
4. [`nonceForPublicKey`](#4-nonceforpublickey)
5. [`actions`](/protocol/transactions/transaction-anatomy#actions)
6. [`blockHash`](#6-blockhash)

### 1 `signerId`

- The `signerId` is the account ID of the transaction originator.
- This value is passed as a string (ex. `'example.testnet'` or `'bob.near'`)

### 2 `signerPublicKey`

- The `signerPublicKey` is required to be an object with two key value pairs: `keyType` and `data`.

```js
const publicKeyExample = {
  keyType: 0,
  data: new Uint8Array([
    190,
    150,
    152,
    145,
    232,
    248,
    128,
    151,
    167,
    165,
    128,
    46,
    20,
    231,
    103,
    142,
    39,
    56,
    152,
    46,
    135,
    1,
    161,
    180,
    94,
    212,
    195,
    201,
    73,
    190,
    70,
    242
  ]),
};
```

- This can be constructed by calling `getPublicKey()` using the `keyPair` we [setup earlier](#access-keys).

```js
const publicKey = keyPair.getPublicKey();
```

### 3 `receiverId`

- The `receiverId` is the account ID of the transaction recipient.
- This value is passed as a string (ex. `'example.testnet'` or `'bob.near'`)
- The certain cases, the `signerId` and the `receiverId` can be the same account.

### 4 `nonceForPublicKey`

- A unique number or `nonce` is required for each transaction signed with an access key.
- For this single-worker example, query the current `nonce` and add one. Production workers must coordinate nonce allocation per sender and access key; independent queries can allocate the same nonce.
- Current nonce can be retrieved using the `provider` we [created earlier](#setting-up-a-connection-to-near).

```js
const accessKey = await provider.viewAccessKey({
  accountId: sender,
  publicKey,
  finalityQuery: { finality: "final" },
});
if (accessKey.permission !== "FullAccess") throw new Error("Full-access key required");
if (accessKey.nonce > BigInt(Number.MAX_SAFE_INTEGER)) {
  throw new Error("Use an RPC decoder that preserves large integer nonces");
}
```

- now we can create a unique number for our transaction by incrementing the current `nonce`.

```js
const nonce = accessKey.nonce + 1n;
```

### 5 `actions`

- See the supported [action types](/protocol/transactions/transaction-anatomy#actions).
- For this example, we are using `Transfer`
- This transfer action can be created using the [imported `transactionActions` helpers](#imports) and the [formatted Ⓝ amount](#formatting-token-amounts) created earlier.

```js
const actions = [transactionActions.transfer(amount)];
```

[[click here]](https://github.com/near/near-api-js/blob/2546c85354ab888dc1f559b0e54cfac51f03b484/src/transactions/action_creators.ts) to view source for `transfer()`.

### 6 `blockHash`

- Each transaction requires a recent block hash (within the configured block-based validity period) to prove that the transaction was created recently.
- Fetch a recent finalized block and convert its hash to bytes using the imported `baseDecode()` helper.

```js
const block = await provider.viewBlock({ finality: "final" });
const recentBlockHash = baseDecode(block.header.hash);
```

[[click here]](https://github.com/near/near-api-js/blob/2546c85354ab888dc1f559b0e54cfac51f03b484/src/utils/format.ts) to view source for `baseDecode()`.

### Constructing the Transaction

With all of our [required arguments](#transaction-requirements), we can construct the transaction.

- Use the imported `createTransaction()` helper to perform this task.

```js
const transaction = createTransaction(
  sender,
  publicKey,
  receiver,
  nonce,
  actions,
  recentBlockHash
);
```

[[click here]](https://github.com/near/near-api-js/blob/2546c85354ab888dc1f559b0e54cfac51f03b484/src/transactions/schema.ts) to view source code for the Transaction class

### Sign Transaction

Now that the transaction is created, we sign it before sending it to the NEAR blockchain. At the lowest level, there are four steps to this process.

1. Use `encodeTransaction()` to serialize the unsigned transaction in [Borsh](https://borsh.io/).

```js
const serializedTx = encodeTransaction(transaction);
```

2. Hash the serialized transaction using a `sha256` cryptographic hashing algorithm.

```js
const serializedTxHash = createHash("sha256").update(serializedTx).digest();
```

3. Create a signature with the `keyPair`.

```js
const signature = keyPair.sign(serializedTxHash);
```

4. Construct the signed transaction using near-api-js [SignedTransaction class](https://github.com/near/near-api-js/blob/2546c85354ab888dc1f559b0e54cfac51f03b484/src/transactions/schema.ts).

```js
const signedTransaction = new SignedTransaction({
  transaction,
  signature: new Signature({
    keyType: transaction.publicKey.keyType,
    data: signature.signature,
  }),
});
```

### Send Transaction

Final step is to encode and send the transaction.

- First we serialize transaction into [Borsh](https://borsh.io/), and store the result as `signedSerializedTx`. _(required for all transactions)_
- Then we send the transaction via [RPC call](/api/rpc/introduction) using the `sendJsonRpc()` method nested inside [`provider`](#setting-up-a-connection-to-near).

```js
// encodes transaction to serialized Borsh (required for all transactions)
const signedSerializedTx = encodeTransaction(signedTransaction);
// sends the signed transaction and waits for finalized execution
const result = await provider.sendJsonRpc("send_tx", {
  signed_tx_base64: Buffer.from(signedSerializedTx).toString("base64"),
  wait_until: "FINAL",
});
if (result.final_execution_status !== "FINAL") throw new Error("Execution is not final");
console.log(result);
```
